# SEMI SECS/GEM Future
- 談半導體 SECS/GEM 未來發展

## 1.前言:
在經歷半導體產業的製程、製造、CIM、MES、建廠等，對於未來的技術、標準、人才及經營的發展有了新的想法及目標，並決定寫下此計畫/策略，供眾人探討及探索未來。

### •	對於新人，在學習 SECS/GEM 的時候，對於內容結構、Stream Functin、Type、Scenario、對應關係，是非常吃力且難以理解的，縱使曾經有過Coding知識和能力，也很難融會貫通。
### 再加上仿間毫無任何資訊可以查閱、官方資訊若非行業內專家提點，難以觸及SECS/GEM核心原理，只知其表象，但不知其原理，最終難以學成。
### •	對於資深專家，在日新月異的半導體製程上，所需要的資訊量及即時高頻反應的要求越來越嚴苛，嘗試過Interface A或是開始自行與廠商定義新的Service 或專屬通道，例如:WebServcie、MQTT、外接更多網路線、sftp，甚至魔改 SECS/GEM 格式內容，捨棄[0], [0] [0] 等結構、A、U2、U4、SVID、對應關係等都不再重視，甚至捨棄部分遠程控制及配方功能，其餘功能更是逐漸式微，導致CIM 系統外加更多服務，並越來越發散。
### 基於結構上的資訊，若無參照文件，新需求或變更需求時，維護上吃力不討好，非直覺。
### •	安全性上，無加密及身分驗證。
### •	一台設備(Passtive)，1次僅能對1台 Host(Active) 連線。
### •	由於SECS/GEM 非 IT 通用協定，僅集中在單一領域，且Binary Protocol解析邏輯，僅掌握在非常古老企業及資深的長者身上，礙於商業考量，難以傳承。
### 即使透過購買Licence，仍有部分資訊或內容，不提供或直接HardCode寫死，迫使製造業者和Vender必須調整或變向修改程式邏輯或另尋客製功能，導致系統的運行及流程上，難以精簡及整合。
### 熟悉此技術的人才越來越稀少。

本文章核心目的是希望藉由各位專家，一同探討或精進，這裡不爭論對錯問題，可望得到或傳承對於未來的半導體自動化協定有更多利於史界的方展，例如:精進 SECS/GEM 發展新一代、整合新穎技術與SECS/GEM結合、放棄目前 SECS/GEM 協定等，都是不同的選擇，最終讓我們未來可以有所不同，共同遵循統一的語言與規範，共同推動技術的創新與進步，大家朝向更好美的方向推進。
